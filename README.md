# 狐朦桌宠

一个基于 Electron 的桌面宠物 app。狐朦平时在屏幕角落站岗，在你专注太久时会突然在屏幕上奔跑，提醒你休息。

## 当前状态

- 透明无边框、置顶、跳过任务栏的桌面宠物窗口
- 狐朦默认在屏幕右下角保持站岗姿态
- 狐朦形象使用用户提供的写实狐獴照片，经绿幕分离后以透明 PNG 显示
- 点击、悬停、快捷键召唤时会做出回应
- 专注提醒触发时，会在屏幕上随机乱窜一圈，再回到原来的角落
- 支持简单的气泡文案反馈
- 右击狐朦可选择“奔跑吧狐朦”“工作时间”“工作安排”或“年龄”
- 右击“年龄”可选择 20%、40%、60%、80%、100% 或 200% 的桌宠大小，设置会保存到本机
- 右击可录入一次性的剩余工作时长（1–480 分钟）；到点后狐朦会奔跑提醒
- 点击狐朦上半身会随机显示内置互动语或你添加的自定义语录；点击下半身显示工时统计
- 右击“添加对话”可添加、编辑、删除自定义语录，内容会保存到本机 app 数据目录
- 可直接拖动狐朦；位置只在当前运行期间保留，提醒奔跑后会回到最后拖动位置
- “奔跑吧狐朦”会立即奔跑，并把当前专注阶段重置为新的工作时间
- “工作时间”会显示今日累计工作时间、当前计时阶段、阶段已用时间和距下次提醒时间
- `Ctrl/Cmd + Shift + Q` 可随时退出 app

## 当前提醒规则

这版的行为规则是为了帮助控制专注时间和休息节奏。默认工作安排为“工作 40 分钟、未休息时每 10 分钟再次提醒、休息 5 分钟”：

- app 启动后，如果你持续工作，工作时间到点后触发第一次提醒
- 第一次提醒时，狐朦会在屏幕上乱窜
- 如果你没有停止工作，下一次提醒会按“再次提醒间隔”触发
- 之后只要还在持续工作，就按该间隔持续提醒
- 如果你停止工作达到设置的休息时间及以上，这次休息会被视为有效休息
- 休息满设置的休息时间时，狐朦会冒出“我们继续吧”气泡，直到你重新操作电脑才消失
- 一旦有效休息成立，下一次开始工作时，提醒计时会重置为新的工作时间
- 系统空闲状态目前每 1 分钟检查一次

说明：

- 休息时间内没有键鼠操作，当前仍视为连续工作；空闲达到设置的休息时间及以上才视为休息
- “停止工作”当前依赖系统空闲时间判断，不区分你是在看屏幕、发呆还是离开电脑
- 因为是基于系统空闲时间判断，所以“重新操作电脑”的识别仍然依赖空闲时间回落到设置的休息时间以内

## 快捷键

- `Ctrl/Cmd + Shift + F`：召唤狐朦到右下角
- `Ctrl/Cmd + Shift + Q`：退出 app

## 右键菜单

- `奔跑吧狐朦`：狐朦立刻沿随机路线奔跑，回到站岗位置后继续守候；当前专注计时同步重置为当前工作时间
- `工作时间`：通过气泡显示今日累计工时和当前阶段。阶段分为“首轮专注”“加时专注”和“有效休息中”
- `添加对话`：打开管理面板，可添加、编辑和删除用户自定义语录；新增语录会与内置互动语一起随机显示
- `录入剩余工作时长`：输入 1–480 分钟，设置一次性自定义倒计时；到点奔跑一次后，恢复当前工作安排的跟进提醒
- `工作安排`：设置工作时间、未休息时的再次提醒间隔和有效休息时间；三个值均为 1–480 分钟，并会保存到本机 app 数据目录，重启后仍然生效
- `年龄`：按 20%、40%、60%、80%、100% 或 200% 缩放狐朦本体；20% 会切换为破壳狐朦，40% 会切换为带奶嘴狐朦，200% 会切换为带圣诞老人胡子和拐杖的老年狐朦
- `退出狐朦`：关闭桌宠；与 `Ctrl/Cmd + Shift + Q` 快捷键效果相同

## 年龄与大小

年龄默认是 100%，选择后会写入本机 app 数据目录的 `pet-age.json`，重启后仍然生效。百分比只影响狐朦本体；气泡、文字和设置面板始终保持原本大小。20% 至 100% 使用相同的交互画布，200% 时窗口会扩展以完整容纳放大的狐朦；拖动与奔跑路线会使用对应窗口尺寸。

## 工作安排

“工作安排”中的三个时间都以分钟为单位：

- `工作时间`：从一轮工作开始到第一次奔跑提醒的时长
- `再次提醒间隔`：第一次提醒后，如果尚未达到有效休息时，每隔多久再提醒一次
- `休息时间`：系统没有键鼠操作多久后，狐朦显示“我们继续吧”并将下一轮工作计时复位

保存新安排时，当前普通工作阶段已经过去的时间会保留，并按新时长重新计算；若新时长已经到点，狐朦会立即提醒。正在运行的“录入剩余工作时长”是一次性覆盖计时，保存工作安排不会中断它；倒计时结束后才使用新安排。

## 点击与拖动

- 点击上半身：随机显示内置互动语或自定义语录
- 点击下半身：显示今日累计工时和当前专注/休息阶段
- 鼠标按住并拖动狐朦：在主屏工作区内移动桌宠；位置只在当前运行时有效
- 发生拖动后，松手不会触发点击气泡；提醒奔跑结束后会回到最后拖动位置

## 自定义倒计时

- 自定义倒计时仅在当前运行期间有效，重启应用后恢复当前工作安排的首轮专注
- 设置新的自定义倒计时、手动“奔跑吧狐朦”或完成有效休息后，之前尚未到点的自定义倒计时会被清除；调整“工作安排”不会清除它
- 点击下半身或选择“工作时间”时，会显示“自定义倒计时”及距奔跑的剩余时间
- 自定义倒计时使用一次性定时器，到点后立即检查系统是否仍处于工作状态再触发奔跑

## 运行

```bash
npm ci
npm start
```

要求 Node.js 22 或更高版本。`npm ci` 会严格按照 `package-lock.json` 安装依赖，适合在另一台电脑或 GitHub Actions 上复现相同环境；只有需要更新依赖时才使用 `npm install`。

### macOS 提示 Electron.app 包含恶意软件

先确认 Electron 来自本项目的 npm 依赖。`npm install`/Electron 官方安装脚本会使用包内校验清单验证下载内容。本项目当前使用 Electron 43.x。

如果 macOS 拒绝 npm 提供的通用开发包，可只为项目内的副本生成本地 ad-hoc 签名：

```bash
cd /Users/lingyizou/Desktop/fumeng-pet
npm run prestart
codesign --force --deep --sign - node_modules/electron/dist/Electron.app
codesign --verify --deep --strict --verbose=2 node_modules/electron/dist/Electron.app

```

验证成功时会看到 `valid on disk` 和 `satisfies its Designated Requirement`。如果系统仍提示阻止，请打开“系统设置 → 隐私与安全性”，在安全提示处选择只对此应用“仍要打开”，然后再次运行 `npm start`。

不要执行关闭 Gatekeeper 的全局命令，也不建议递归删除隔离属性。重新安装或升级 Electron 后，本地签名可能需要重新生成。

## 代码结构

- `src/main.js`
  Electron 主进程。负责创建窗口、角落定位、系统空闲时间检查、可配置提醒调度，以及乱窜路线生成与窗口移动。
- `src/preload.js`
  预加载桥接层。把主进程事件安全暴露给渲染层。
- `src/renderer.html`
  桌宠页面结构。包含站岗姿态的写实狐獴透明图片和反馈气泡。
- `src/styles.css`
  外观与动画。包括狐朦站岗、回应、奔跑、尾巴动作和气泡样式。
- `src/renderer.js`
  前端互动逻辑。负责上/下半身点击、语录管理、拖动、气泡文本和视觉反馈。
- `scripts/ensure-electron.js`
  启动前依赖自检。检测并修复 Electron 可执行程序缺失造成的 `spawn ... ENOENT`。
- `scripts/remove-chroma.js`
  将均匀绿幕 PNG 转成带透明通道的紧凑桌宠素材，并处理边缘绿色溢色。
- `src/assets/humeng-guard-chroma.png`
  从用户参考照片生成的绿幕中间素材，保留用于重新调整透明边缘。
- `src/assets/humeng-guard.png`
  桌宠当前使用的写实狐獴透明素材。
- `src/assets/humeng-hatchling.png`、`src/assets/humeng-pacifier.png`、`src/assets/humeng-elder.png`
  年龄特殊形态使用的完整透明素材。

## 主要实现说明

- 狐朦本体使用透明 PNG，年龄切换时更换对应静态素材
- “乱窜”是通过移动透明 Electron 窗口实现的，不是在同一个窗口内部平移图片
- 提醒调度在主进程完成，避免前端自己定时导致逻辑分散
- 右键菜单使用 Electron 原生菜单，关闭菜单后不会在透明窗口里留下额外面板
- 工作时间按系统活跃状态逐秒累计，并写入本机 app 数据目录的 `work-stats.json`
- 工作安排写入同一目录的 `work-schedule.json`，首次运行默认使用 40/10/5 分钟
- 自定义语录写入同一目录的 `custom-dialogues.json`；拖动位置不写入磁盘
- 当前只使用主屏幕 `workArea`

## 性能与负担

这版对电脑的负担总体不大，但它仍然是一个 Electron 常驻 app，所以不是零成本。

- 常驻成本主要来自 Electron 自身的内存占用
- CPU 平时很低，主要工作是每 1 分钟检查一次系统空闲时间
- 乱窜时会短暂增加一点窗口移动和动画重绘开销
- 当前实现没有复杂数据处理、网络请求或后台索引任务

如果后续要继续降负担，优先方向通常是：

- 继续减少无意义轮询
- 减少动画频率和透明窗口重绘
- 最终改成更轻的原生实现
